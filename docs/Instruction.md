# 操作 Instruction

## 1. 接线

先断开电源。GPIO 编号指开发板丝印，不是排针位置。所有模块共地。

### 屏幕与触摸

实物标识为 2.4 英寸 TFT SPI 240×320，横屏使用 320×240。固件按 ILI9341 / XPT2046 协议运行。

| 屏幕针脚 | ESP32-S3 连接 | 用途 |
|---|---|---|
| T_IRQ | GPIO4 | 触摸中断 |
| T_DO | GPIO13 | 触摸数据返回 |
| T_DIN | GPIO15 | 触摸数据发送 |
| T_CS | GPIO5 | 触摸片选 |
| T_CLK | GPIO16 | 触摸时钟 |
| SDO / MISO | 不接 | 当前不读取显示芯片 |
| LED | 3V3 | 当前背光接法 |
| SCK | GPIO12 | 显示时钟 |
| SDI / MOSI | GPIO11 | 显示数据发送 |
| DC | GPIO7 | 命令与数据选择 |
| RESET | GPIO6 | 显示复位 |
| CS | GPIO10 | 显示片选 |
| GND | GND | 地 |
| VCC | 3V3 | 当前模块供电接法 |

VCC、LED 接 3V3 是现有使用记录；换屏幕时需核对新模块的额定电压和背光电路，不能按外形沿用。

### SCD41

| 模块丝印 | ESP32-S3 |
|---|---|
| GND | GND |
| VDD | 3V3 |
| SCL | GPIO9 |
| SDA | GPIO8 |

固件使用 I²C 地址 0x62、100 kHz，无需新增 SCD41 库。不自动执行强制校准，也不修改传感器 ASC 设置。

### 四线风扇

现有风扇：FCN DFS1401055G0T，标称 5V、0.3A。以下是用户现有接线，GPIO17/18 为后续控制预留；当前运行固件不输出 PWM、不读取转速。

| 风扇线 | 连接 |
|---|---|
| 电源正极 | 外部 5V 正极 |
| GND | 外部电源负极，并与 ESP32 GND 共地 |
| TACH | GPIO18，接入前确认电平不超过 3.3V |
| PWM | GPIO17，后续驱动前确认该型号的输入电平及开漏要求 |

不能仅按线色判断定义，也不能把 5V 风扇接到 12V。风扇模拟曲线不代表已实现实际风扇控制。

### 830 孔面包板与杜邦线

- 同一数字行内 a–e 相通，f–j 相通，中间槽两侧不通；相邻数字行不通。
- 屏幕每根针脚占一行，从同组剩余孔接出。若排针插在 d 列，可从同一数字行的 e 孔接线。
- 电源长轨可能在中间断开，先用万用表确认连通；印着同样的 +/− 不保证整条相通。
- ESP32 太宽时可以放在面包板旁边，用母头套排针、公头插面包板；无需强行把整块板插入。
- 屏幕 VCC、LED、SCD41 VDD 可共用一条 3V3 电源轨，各 GND 共用地轨，可减少开发板供电引出线。
- 只在排针附近适度垂直施力，不能压玻璃或弯曲 PCB；插不进先检查针距、方向和孔位。

## 2. 供电

USB 调试时由 USB 给 ESP32 供电。外接供电路径为：

```text
12V 电源 → 降压模块 → 稳定 5V
                       ├─ ESP32 的 5V/VIN 与 GND
                       └─ 5V 风扇与共地
ESP32 的 3V3 → 屏幕 VCC、LED 和 SCD41 VDD
```

先空载测量降压输出，再连接设备。开发板 3V3 稳压器需同时负担 ESP32、传感器和背光，USB 供电能力不能直接当作 3V3 输出能力。没有核实开发板电源隔离电路前，不同时接外部 5V 和 USB 5V。

## 3. 编译与上传

电脑需安装 Arduino IDE / arduino-cli、ESP32 开发板平台及 `Chirale_TensorFLowLite` 2.0.0 库。传感器通信使用 ESP32 平台自带 Wire。

| 选项 | 当前配置 |
|---|---|
| 开发板 | ESP32S3 Dev Module |
| USB Mode | Hardware CDC and JTAG |
| USB CDC On Boot | Enabled |
| Upload Mode | UART0 / Hardware CDC |
| Flash Size | 16MB，与项目已记录的实测容量一致 |
| Partition Scheme | Custom，使用 firmware/partitions.csv |
| 串口波特率 | 115200 |

先按实际芯片容量核对设置；日志若显示只有 4MB，不能继续使用 16MB 分区。具体 FQBN 和编译并行数保存于 `firmware/build.json`。

在项目根目录执行：

```powershell
# 编译；不上传、不接触板上记录
& ./.venv/Scripts/python.exe tools/firmware.py
# 编译成功后上传，端口按实际枚举修改
& ./.venv/Scripts/python.exe tools/firmware.py --upload --port COM4
```

Arduino 要求主 ino 名称与工程目录同名。当前入口 `firmware/firmware.ino` 符合该规则，可直接用 Arduino IDE 打开，并应用上表设置。构建工具直接编译 `firmware/`，不需要复制临时工程。

## 4. 触摸校准与界面

启动优先复用 NVS 中有效触摸矩阵；缺失、损坏或屏幕方向不匹配时显示四角校准。依次按住十字中心，目标移动后松开，再按下一个。完成后自动保存。设置页“触摸校准”或串口 `r` 可重新校准，不清除采集文件。

| 页面 | 操作 |
|---|---|
| 主页 | 保留左侧 CO₂、状态、温度和湿度，右侧趋势图；点击图表列切换 5/15/30/60 分钟历史 |
| 控制 | 自动/手动及 0/33/66/100% 目标档位预览 |
| 设置 | 显示固件版本；两行三列：SCD41 状态、恢复连接、触摸校准、数据记录、调试、TinyML 开关 |
| 数据记录 | 选择教室/卧室/户外/密闭，开始或停止记录，查看容量和异常 |
| 调试 | 点击顶部分页切换采样历史、模型性能、存储运行；模型页可切换日志 |

v1.12.0 界面取消原顶部标题、时钟和“实测”栏，保留原双栏主页、字体、状态胶囊与底部导航。未来预测固定 +5/+15 分钟；陶土虚线为延续预测，浅橙虚线为风扇情景模拟，图下两个数值均对应 +15 分钟。曲线原点取最新完整分钟均值，大字读数取最新原始测量，两者可能略有差异。主页状态胶囊显示采集中、历史缺口、未覆盖、可预测或已关闭，具体诊断在调试页查看。

TinyML 首次默认开启，设置页开关会保存并在重启后沿用。关闭立即清空预测并停止推理，采样、分钟历史与原始记录继续；重新开启无需重启传感器，仍需满足 20 个连续有效分钟。开关保存失败时页面显示错误，本次运行的开关仍生效，但不能保证重启后沿用。

实时预测只使用 CO₂，相对运行时间即可，无需 USB 校时。每分钟至少 8 条成功读数且没有读取错误；启动、恢复或导出造成的缺口退出最近 20 分钟窗口后才能预测。v1.11.2 的 CO₂ 输入量化覆盖约 350～5,000 ppm，温湿度只记录、不参与预测范围判断。

## 5. 开始记录与导出

设置 → 数据记录 → 选择环境 → 开始记录。记录中环境锁定，需停止并开启新场次才能切换。不强制校时；未校时时日期为空，相对运行时间仍保存。

首次存储未挂载时提供“初始化存储”。初始化会清空文件系统；已有数据但挂载失败时先排查，不能把初始化当作普通恢复。正常启动不会自动格式化。

关闭串口监视器后执行：

```powershell
& ./.venv/Scripts/python.exe tools/export_recording.py --port COM4 --output co2-recording.csv
# 可按十位场次编号导出
& ./.venv/Scripts/python.exe tools/export_recording.py --port COM4 --session 0000000001 --output session-0000000001.csv
```

文件名需未被使用。导出保留板上记录；失败留下 `.partial` 文件，不能作为完整数据使用。导出期间采样暂停，应避开实验关键阶段。导出不改变记录开关：原本记录中则完成后继续当前场次，已停止记录则保持停止。

电脑端先按块接收 USB 原始流，再校验并转换 CSV；每次在 `.build/recording-export-*.raw.log` 保留独立原始日志。只有收到结束标记且序号、场次和总条数校验通过才生成正式 CSV。超时后保留日志与 `.partial` 排查，不把临时文件当成完整导出，也不初始化存储。

v1.12.1 源码为 USB 连接暂态和发送停滞增加有界等待，按实际写入长度续传；仅升级电脑端脚本不会改变旧板端行为。主机保持 DTR/RTS 为 false，避免擅自改变控制线；本机 ESP32 `3.3.10-cn`、`USBMode=hwcdc` 的源码并非直接用 DTR/RTS 决定连接布尔值。此版本尚待实机长记录导出验收，失败时仍应保留原始日志和临时文件。

## 6. 可选 USB 校时与串口命令

串口使用 115200。校时发送 `T` 加电脑当前 ISO8601 时间和换行，例如 `T2026-10-12T12:00:00+08:00`；示例日期需要换成实际时刻。设备没有 RTC，断电或重启后需重新校时。

| 命令 | 功能 |
|---|---|
| s | 查询界面与预测状态 |
| p | 切换 TinyML 预测并保存开关，采样和原始记录继续 |
| r | 重新触摸校准 |
| q | 恢复传感器测量，保留历史与当前场次 |
| b / x | 开始 / 停止记录 |
| l | 查询记录状态与容量 |
| e | 导出全部场次 |
| i | 初始化未挂载的存储，会清空文件系统 |
| T+ISO8601 | 可选主机校时，需换行结束 |

## 7. 故障排查

| 现象 | 检查方法 |
|---|---|
| 白屏、有背光 | 核对显示信号、GND、3V3；背光亮不代表程序已启动 |
| 只插外部电源白屏 | 测量 5V/VIN 与 3V3，检查降压输出和共地；查看启动日志 |
| 触摸无响应 | 核对 T_IRQ、T_CS、T_CLK、T_DIN、T_DO；重新校准 |
| CO₂/温湿度为 -- | 核对 SCD41 供电和 GPIO8/9，点击恢复连接或发送 q |
| 采集中 | 缺少 20 个连续有效分钟；可继续保存原始数据 |
| 历史缺口 | 调试 → 采样历史，查看连续有效分钟、首个坏分钟及样本数/原因；一次错误也会使整分钟无效，需等坏分钟退出最近 20 分钟窗口 |
| 未覆盖 | CO₂ 历史超出当前模型的 int8 覆盖范围；不是触摸故障 |
| 存储空间不足 / 写入失败 | 写入已停止，先导出；程序不自动删除旧场次。读写失败状态显示“请重启”，重启后重新检查存储再开始；重启不保证空间不足或存储故障已解决 |
| partition exceeds flash chip size | 核对实际 Flash 容量、build.json 和 partitions.csv，重新编译上传匹配分区 |
| No serial data received | 关闭占用串口的程序，核对接口与端口；必要时 BOOT+RESET 进入下载模式 |

如果出现短路、发热或 USB 反复断连，断电检查。分区调整或全片擦除可能删除日志与 NVS 校准参数。
